eris-validation: design

Agreed 2026-11-03 by Victoria Sjalim with Claude (design review, five rounds).

Goal

Measure how well eris reports, for each IS, which CDS lies upstream and downstream, how far away it is, and whether the insertion disrupts it. Report precision, recall and F1 for side, distance and effect, and a row-level table of every wrong prediction. Run it on any genome with Snakemake.

Terms are defined in CONTEXT.md. Why the scorer lives here and not in eris: ADR 0001.

Inputs

Per assembly, one row of config/samples.tsv:

column meaning
genome e.g. EC958
assembly_type complete, simulated or real
assembly FASTA or GFA given to eris
reference complete reference genome FASTA, used to place eris genes
gff RefSeq GFF of the reference
is_bed IS positions on the reference: name, start, end, strand
curated optional curated relation table (side and effect per IS)
replicons optional; limit the truth to these replicons (simulated EC958 GFA is chromosome-only)

config/config.yaml holds everything that is not per assembly:

  • eris: git URL and commit to install (default adimascf/eris main). The commit is written into every metrics row.
  • is_db: ISfinder minimap2 index (data/IS_n.mmi). The workflow stops if it holds only a handful of sequences (the EC958 genome index data/IS.mmi was once used by mistake and made a GFA run hang).
  • eris settings: collapse mode, min_coverage 0.30, scored run hops 3, reach run hops 20.
  • Scoring thresholds (Dimas’s values, so results compare with eris’s own benchmark): placement overlap ≥ 50% of the shorter gene, near band ≤ 150 bp, nucleotide check ≥ 99% identity and ≥ 80% CDS coverage.

Isoform groups are fetched as data from tests/isoform_groups.tsv at the pinned eris commit.

Steps

  1. Install eris at the pinned commit (conda env).
  2. Build truth (erisval build-truth): for each IS in is_bed, the nearest CDS on each side from the GFF, upstream/downstream relative to the IS’s strand. Coordinates, strand, partial/pseudo and distance come from the GFF. Effect is disrupted when the CDS overlaps the IS or is partial/pseudo. If a curated table is given, its side and effect override the automatic ones, and disagreements go to truth_review.tsv. A CDS inside a neighbouring IS stays a flank with its effect unscored; upregulated and uncertain effects are kept but unscored.
  3. Run eris twice per assembly (hops 3 scored, hops 20 reach), producing _report.tsv and _cds.fna.
  4. Score (erisval score): reads _report.tsv, _cds.fna, the reference and the truth. Does not import eris.
    • Join report genes to _cds.fna: by gene_id (<contig>_<start>_<end>, 0-based) when records carry it, else by the coordinates in older pyfgs-style records (<contig>_FGS_<n>, 1-based). A reported gene missing from the FASTA stops the run.
    • Place each gene on the reference with minimap2; very short genes by exact search. A gene with several equally good placements matches if any of them does.
    • Match: same replicon, same strand, overlap ≥ 50% of the shorter of the two.
    • IS names: copy suffix stripped, then mapped to their isoform group. No family fallback.
  5. Combine every assembly’s metrics into results/metrics.tsv.

Scoring rules

  • Relation key: (isoform group, side, locus tag).
  • Recall: truth relations found on their side. Pooled recall also accepts the wrong side.
  • Precision: over first flanks only (nearest flank per side per graph branch), because the truth holds only the nearest CDS.
  • Wrong side is strict: FN on the true side and FP on the reported side, marked FN_wrong_side / FP_wrong_side.
  • Unplaceable genes (no placement on the reference) count as FP, marked FP_unplaceable.
  • Distance: on relations found on their side, truth and eris distances binned into overlapping (< 0, or eris overlap context), near (0–150 bp), far (> 150 bp). P/R/F1 per band, band agreement, and absolute error (median, max, share within 10 and 50 bp). eris reports overlaps as 0.
  • Effect: only disrupted is scored. eris DISRUPTED or TRUNCATED counts as disrupted. Upregulated is shown in the matrix, not scored.
  • Miss cause: a miss found by the hops-20 run is budget, otherwise gene.
  • Reports only: no pass/fail. eris’s own EC958 ratchet stays the only gate.

Outputs

Per assembly in results/<genome>/<assembly_type>/:

file content
truth.tsv, truth_review.tsv built truth; curated-vs-recomputed disagreements
side_confusion.tsv truth side (upstream, downstream, no_truth) × eris side (upstream, downstream, not_reported)
distance_confusion.tsv truth band × eris band
effect_confusion.tsv truth effect (disrupted, none, unscored) × eris effect
metrics.tsv long format: dimension, class, metric, value
relations.tsv one row per truth relation and per false flank: status, IS, side, locus tag, eris gene, both distances, both effects, distance_band_ok, effect_ok, miss cause, nucleotide check

results/metrics.tsv combines them with genome, assembly_type, eris_commit columns.

Layout

eris-validation/
  workflow/Snakefile, rules/*.smk, envs/*.yaml
  config/config.yaml, samples.tsv
  src/eris_validation/   truth.py, place.py, score.py, tables.py, cli.py
  tests/                 synthetic genome + unit tests; EC958 end-to-end (skipped without data/)
  docs/design.md, docs/adr/
  CONTEXT.md, README.md

Python with pandas, mappy and Biopython; Snakemake ≥ 8 with conda. Genome data stays out of git. Built test-first: a tiny synthetic genome (about three IS on both strands, flanks on each side, one overlapping, one far) with a hand-written eris report containing known errors, whose P/R/F1 is worked out by hand.

GitHub: Victoriasja18/eris-validation.
