How eris's IS–CDS relations are scored

For each insertion sequence, eris reports which CDS sits upstream and downstream and how far away. This guide explains every status and reason the scorer gives, using real cases from the EC958 real-read assembly.

Counts come from the 13 Nov 2026 run of eris 7b9a6dc, before the best-score naming fix e9887c1. That fix brings FN wrong_IS on the real assembly from 24 down to 11.

Two views of the same calls

The scorer reads eris's output from two directions, and each direction answers a different question.

Recall: every truth relationA truth relation is one CDS on one side of one IS in the reference. Did eris report that CDS, on that side, under that IS's isoform group, at any flank? The answer is TP or FN.
Precision: every eris first flankA first flank is eris's nearest reported gene on one side of one graph branch of a locus. It is eris's actual claim. Is that claim a truth relation of this IS on this side? The answer is TP or FP.

Because the two views overlap, one wrong call can produce two rows: an FN for the truth it missed and an FP for the wrong claim it made. That is correct, not double counting. Each row feeds a different metric.

Proposed change to the reasons

Two of the reasons mean the same thing whether they appear on an FN or an FP row. Only one is misleading: FN wrong_IS also fires when the gene appears only as a deep flank of an unrelated locus, kilobases away, where eris never claimed it.

None of this changes precision, recall or F1. It changes only how misses and false calls are labelled in relations.tsv and counted in details.tsv. Turning the FN rows into FPs instead would remove them from the recall denominator and make recall look better than it is.

Distance bands

Distance is the gap in base pairs between the IS end and the nearest end of the flanking CDS. The truth gives a negative distance when the CDS runs into the IS. eris reports an overlap as 0 bp with an OVERLAPPING context.

Why FN and FP rows have no distance score

A distance comparison needs two numbers for one gene. An FN not_found has no eris distance, and an FP not_in_truth has no truth distance. A deep-flank FN wrong_IS does have an eris number, but it measures the distance to a different IS, so comparing it with the truth would mix two measurements. These rows already count once in the side scores; adding them to distance would count the same miss twice.

What the distance numbers say

16 of the 23 band disagreements on the real assembly have an error of 0 bp. They come from how 0 bp and overlaps are defined, not from eris placing genes in the wrong spot:

  • Touching (9 rows). The truth counts 0 bp as near, because only a negative distance is overlapping. eris calls the same 0 bp overlapping.
  • Hidden overlap (7 rows). The truth says the CDS runs into the IS, for example by 65 bp. eris reports 0 bp without flagging an overlap, and the error formula then gives 0, so the overlap disappears from the numbers.

That is why the overlapping band scores so badly while the median error is 0 bp. Two possible fixes: treat 0 bp as overlapping on both sides, and record separately whether truth and eris agree that the CDS overlaps the IS.

Real distance errors do exist: IS1A_2 to RS30330 is 101 bp in the reference and 287 bp in eris, and IS682 to tnpC overlaps by 2 bp in the reference but is 604 bp away in eris, probably measured from a different IS end.
